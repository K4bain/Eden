# To Spec

Takes conversation context and codebase understanding, produces a spec (PRD). Do NOT interview — just synthesize what you already know.

## Process

1. Explore the repo to understand current state
2. Sketch out test seams (prefer existing seams)
3. Write the spec using the template
4. Publish to issue tracker

## Spec Template

- Problem Statement (from user's perspective)
- Solution (from user's perspective)
- User Stories (extensive, numbered)
- Implementation Decisions (modules, interfaces, architecture)
- Testing Decisions (what makes a good test, which modules)
- Out of Scope
- Further Notes
